# APIMatic: SDKs and developer portal

Seed's partner story: another lender verifies a member's credit record, reads the public safety-fund summary and starts a donation, through an SDK and a developer portal generated by APIMatic from our OpenAPI.

## What is here

| Path | What |
| --- | --- |
| `src/APIMATIC-BUILD.json` | Portal build file: spec folder and SDK languages |
| `src/spec/seed-partner/seed-partner-api.yaml` | Curated partner spec (OpenAPI 3.1): 3 public routes of `contracts/openapi/seed-api.yaml` |
| `src/content/toc.yml`, `src/content/guides/*.md` | Portal navigation and guides |
| `../.github/workflows/apimatic-portal.yml` | CI that generates the portal |
| `../examples/partner-lender/` | Plain-HTTP lender script and SDK how-to |

The CLI help says `--input` is "the parent directory containing the 'src' directory", so the build files live in `apimatic/src/`. Docs describe the same files (`APIMATIC-BUILD.json`, `content/`, `spec/`, `static/`) without naming `src`. If your CLI version wants them at the root, move the contents of `src/` up one level.

The partner spec is a copy. When you change those three routes in `contracts/openapi/seed-api.yaml`, change the partner spec too.

## Preview locally

```bash
npm i -g @apimatic/cli@1
apimatic auth login
cd apimatic
apimatic portal serve
```

`apimatic portal generate --input=. --destination=portal` writes the portal to disk. Check `apimatic portal generate --help` for your version.

## CI

`.github/workflows/apimatic-portal.yml` runs on manual dispatch and on pushes to `main` that change `apimatic/**` or `contracts/openapi/seed-api.yaml`. It needs the repository secret `APIMATIC_API_KEY`. Without it, the job prints a message and skips. It uploads the generated portal as the `seed-developer-portal` artifact. It does not deploy.

## Submission checklist (Best Use of APIMatic)

- [ ] Generate the portal (locally or from the workflow) and open it.
- [ ] Publish the portal and note its URL.
- [ ] Generate the SDK (TypeScript at least) and keep the repo or a zip of it.
- [ ] In the demo video, show a partner running the verify check (`examples/partner-lender`, then the SDK version).
- [ ] Mention the spec is curated from our real contract, with examples on every response, `429` with `Retry-After`, and RFC 9457 errors.
